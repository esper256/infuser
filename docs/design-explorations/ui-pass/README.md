# UI pass review

Open `index.html` for the combined screenshot review. The Library grid now links
to [the complete Nightglass mockup](../nightglass-library/index.html), with nine
fictional games, generated full-bleed artwork and author-portrait reactions. All captures use local mock
API responses, not production accounts, games, events, or credentials.

## Changed

- Consolidated the accumulated CSS into one palette, material, spacing and focus treatment.
- Quiet header, presence and categories; compact split Play controls; right-aligned card hierarchy.
- Shared smoked-glass dialogs, readable copyable prompt, compact tag picker, large positive emoji and restrained event bubbles.
- Mobile layouts, keyboard focus, touch targets, reduced motion and forced-color select fallback.
- Shorter static copy and a loading status. Existing IDs, form fields, Google asset and scripts are preserved.

The separate Nightglass option now makes the author portrait the reaction control.
Hover/focus shows “React to KwamiKwami’s game”; click, Enter or tap opens the picker.
No second React button. The portrait is explicitly a placeholder in this prototype.
This direction is recorded in `docs/design.md`.

## Checked

Chromium with a temporary Playwright mock API: desktop 1280px; phones 320, 360 and
390px; signed-out desktop, phones and landscape; search/category filtering;
tag creation/save and an overflowing 48-tag catalog; all six reaction types
wrapping inside a narrow card; emoji-only and comment submission; prompt creation
and clipboard content; guest launch; admin panel; empty/search/error/loading
states; dialog overflow; keyboard focus; reduced motion; no JavaScript errors.
The Nightglass prototype was checked at 320/360/390/768px, with keyboard opening,
Escape/focus return and an actual touch-enabled 320px browser context.

No backend or SDK changes or tests. No deployment, real sign-in, or production API calls.
Browser coverage is Chromium only. Mock verification does not establish backend integration.

## Remaining separate work

Production cards still use the existing abstract marks and reaction control.
Game-provided heroes, creator portraits and the portrait reaction binding need
an agreed data contract and JavaScript work. No author identity, avatar, unread
state, or per-game art has been invented in production. Existing dynamic copy
is unchanged where generated by `web/clubhouse.js`. The player title bar and
networking are outside this pass.
